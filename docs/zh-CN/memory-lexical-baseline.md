# 记忆词法检索基线（M00）

> 状态：完成  
> 冻结日期：2026-09-03  
> 对应实现：`src/memory/evaluation/`、`src/memory/memory-retrieval-baseline.test.ts`

## 目的

本基线冻结 Zvec 接入前 `MemoryService.buildContext()` 的真实检索行为。后续 M02、M08、M09 必须使用同一组 fixture 对比，不能用只适合向量检索的新数据集替换旧基线。

评测会通过现有事件捕获和 dream 流程生成 L2 记忆，再调用生产词法检索路径；它不访问网络，也不替换线上检索器。

## 数据集

- 10 条中英文记忆，覆盖运行失败、Channel 路由、迁移、Desktop 品牌、A2A、Docker/pi 与角色职责。
- 9 个查询，覆盖精确匹配、英文改写、中文改写、实体、失败模式、时间冲突、Leader scope 隔离和无结果查询。
- 7 个查询具有期望相关文档；越权和无结果查询用于测量错误注入。

## 冻结结果

| 指标 | 当前值 |
| --- | ---: |
| Recall@5 | 0.7143 |
| MRR | 0.7143 |
| 错误注入查询率 | 0.2222 |
| 错误注入文档率 | 0.1463 |

延迟由每次测试以 P50/P95 诊断值输出，不冻结为精确断言；并行构建和机器负载会明显影响毫秒级结果。M09 应在固定环境中重新建立性能门槛。

当前已确认的不足：

- 英文同义改写不能召回目标记忆；
- 中文语义改写不能召回目标记忆；
- 无结果查询仍可能注入五条无关记忆；
- 查询历史失败模式时，可能同时注入已经过时的处理方式。

## 运行方法

```bash
pnpm run test:memory:baseline
```

测试会断言排名和四个质量指标，并打印各查询命中、错误注入及 P50/P95。若生产词法行为发生有意变化，必须先解释变化，再更新本报告和冻结断言。
